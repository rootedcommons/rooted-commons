# Rooted Commons v2.9.0 setup

## 1. Members table

Add or confirm these fields before deploying the signup form:

- `Phone` — Single line text. Required by signup.
- `Preferred collection day` — Single select: `Thursday`, `Friday`, `Saturday`, `Sunday`.
- `Membership consent` — Boolean.
- `Membership consent at` — Date/time.
- `Weekly newsletter` — Boolean. This replaces the old signup use of `Marketing consent`; it records the optional choice to include Rooted Commons news and updates in the weekly service email.

The existing `Weekly commitment` field remains the canonical weekly-equivalent amount and accepts penny increments. Add/confirm `Monthly equivalent` (Number, 2 decimals) and `Contribution frequency` (Single select: `Weekly`, `Monthly`). Signup stores the member's chosen amount in the matching frequency field and calculates the equivalent in the other field. Minimums are £10.00/week or £43.34/month.

The runtime token must retain Create permission on Members and Read permission on Collection Points so signup can validate the selected day/location before creating the member.

## 2. Collection Points table

The signup form uses the existing day-specific time fields:

- `Thursday collection time`
- `Friday collection time`
- `Saturday collection time`
- `Sunday collection time`

Blank time = that location is unavailable on that day.

For the `/collection-points/` OpenStreetMap map, add:

- `Latitude` — Number / decimal degrees
- `Longitude` — Number / decimal degrees

Example coordinates: `51.234567`, `-0.765432`. Only active points with both coordinates are plotted. Marker popups use the existing Image, Name, Address and day-specific collection times. Images fill the popup width and retain their natural aspect ratio.

The Pages table should contain an active `collection-points` row. The included Pages import contains a starter row; the user's Baserow-managed page hero/sections remain the editable page copy.

## 3. Interface Content

If `Area` is a single select, ensure `Signup` is an allowed option. Add/import the current `signup.*` rows from `baserow-imports/13-interface-content.csv`.

The new signup copy covers phone usage, preferred day, late-collection guidance, collection-point map link, £10 minimum commitment, weekly secure-link explanation, optional weekly-newsletter consent, and terms/privacy wording.

## 4. Cloudflare Turnstile

Create a Turnstile widget for `rootedcommons.uk` and add these environment variables to the website deployment:

- `PUBLIC_TURNSTILE_SITE_KEY` — public site key; available at build time.
- `TURNSTILE_SECRET_KEY` — secret key; server-side only.

The form will not submit without the site key, and `/api/signup` fails closed if the secret is missing. The server verifies the Turnstile token before reading/writing member data.

The endpoint also applies a best-effort per-worker rate limit of 5 signup attempts per IP per 15 minutes. Because Cloudflare Pages workers can run in multiple isolates, this is an additional guard rather than a globally consistent rate limiter. A Cloudflare WAF/rate-limiting rule for `/api/signup` can be added later if stronger global enforcement is needed.

## 5. Membership terms

`/membership-terms/` is a coded working draft and is linked from the signup consent checkbox and site footer. Review the commercial/legal wording before public launch, particularly the treatment of residual Member Credit when membership ends.

The current draft says members should stop future contributions and spend down their balance before leaving; Member Credit is not ordinarily cash-withdrawable on demand; a residual balance may be offered as a participating-partner voucher/gift card or another reasonable arrangement, while preserving any refund/remedy required by law.

## 6. Welcome and weekly member emails

The website now records the permissions and creates the member immediately, but scheduled email delivery is not generated by the static site itself.

Recommended Baserow/email workflows:

- **Welcome email:** trigger when a new active Members row is created; send the member's secure dashboard/market link and standing-order instructions.
- **Friday weekly service email:** schedule for every active member; send their unique secure link to the following week's market.
- If `Weekly newsletter = true`, the Friday email may additionally contain occasional Rooted Commons news and updates. If false, keep the Friday message operational/service-only.

These emails do not need to control whether the signup row is saved; `/api/signup` creates the member directly.
